# 使用说明与手工验收清单

## 1. 安装

```bash
# 把 <profile> 换成你的 profile 名；桌面版默认 desktop
dsh plugin --profile <profile> add dsh-human-alert
```

本地开发（代码就在本目录时）：

```bash
dsh plugin --profile <profile> add link:C:\Users\fzy\Desktop\dsh-human-alert
```

装完做两件事：

1. **重启 DSH**（或让宿主重新加载 profile）——宿主侧模块是进程内缓存的，改代码/新装都不会自动生效；
2. **刷新浏览器页面**——客户端半侧（`./client`）在页面启动时随 `__DSH_BOOT__` 注入。

刷新后侧边栏应出现「人工确认提醒」入口（铃铛图标）。

> v0.3 改了宿主侧代码（新增长轮询端点 `/wait`），**必须重启 DSH** 才会生效。
> 判断有没有生效：`curl -s "http://127.0.0.1:19387/dsh-human-alert/state?x=1"` 的返回里是否有 `revision` 字段。

## 2. 第一次使用

1. 点侧边栏入口 → 打开面板（首帧是骨架，正文会立刻补上）。
2. 在「桌面通知」分组看**通知权限**：
   - 显示「已授权」→ 直接跳到第 3 步；
   - 显示「尚未授权」→ 点「申请权限」，或直接点测试按钮（点击本身就算用户手势）。
3. 点右上角**测试审批** → 右下角应出现系统通知（标题 `【人工审批】…`），并听到提示音。
4. 点**测试完成** → 应出现 `【任务完成】…` 的通知。
5. 把 DSH 最小化，再点一次测试（或等一次真实审批）→ 通知仍然出现。

> 如果最小化后收不到，先看 Windows 的「专注助手 / 勿扰模式」是否压掉了通知。

## 3. 配置项逐条说明

### 总开关
| 项 | 说明 |
|---|---|
| 启用提醒 | 关掉后**不弹通知、不响铃**，但日志照常写入 |

### 提醒类型（两类各自独立）
| 项 | 说明 |
|---|---|
| 【人工审批】提醒 | 工具调用要你审批、或 agent 用 `ask_user_question` 提问时提醒 |
| 【任务完成】提醒 | 某一轮任务**正常跑完**时提醒（取消 / 报错 / 被拦截 / 超长都不算） |

### 桌面通知（主通道）
| 项 | 说明 |
|---|---|
| 系统桌面通知 | 右下角独立系统通知：DSH 最小化、切到别的窗口也能看到，不抢焦点 |
| 通知权限 | 只读展示 + 「申请权限」按钮。被系统拒绝时插件会回退到应用内弹窗 |

### 应用内弹窗（兜底）
| 项 | 说明 |
|---|---|
| 应用内弹窗 | 默认关闭。系统通知弹不出来时自动用它兜底；打开则两个通道都弹 |
| 始终置顶 | 应用内弹窗覆盖在所有内容之上，页面滚动不影响 |
| 自动关闭 | 单位秒，范围 0–600。填 **0** 表示不自动关 |

### 声音
| 项 | 说明 |
|---|---|
| 声音提醒 | 关掉就完全静音。纯系统通知时提示音由**系统**播放 |
| 提示音 | 内置合成音（应用内弹窗时使用）/ 自定义音频 URL |
| 音量 | 0–100，超出会被钳制到边界 |
| 持续响铃 | 一直响到你确认；只在有应用内弹窗时生效（没有确认按钮时不会无限响） |

### 提醒文案
两类各一套：**标题 / 提示文案 / 确认按钮文字**。标题会拼在类型标记后面，
例如标题填「需要你拍板」→ 通知显示 `【人工审批】需要你拍板`。
超长会截断到 500 字符，全空白会回落默认值。

### 日志
记录每次提醒的**本地时间、类型标记（【人工审批】/【任务完成】）、来源（工具审批/提问/轮次结束）、
工具名、会话 id**，最多保存 200 条（界面渲染最近 50 条），超出丢最旧的。
不记录提问正文或任何对话内容。可一键清空。

## 4. 数据存放在哪

浏览器 `localStorage`：

| 键 | 内容 |
|---|---|
| `dsh-human-alert:settings:v1` | 设置（值里带 `version: 3`） |
| `dsh-human-alert:log:v1` | 提醒日志（值里带 `version: 2`） |

键名沿用 v1（改键等于把老设置清零），版本号写在值里：
v1 的旧文案会自动迁移成「人工审批」文案；v2 升级到 v3 时会把「应用内弹窗」一次性关掉（桌面通知接管），
之后用户手动打开的设置会被记住。

### 通知权限没有授权怎么办

| 环境 | 做法 |
|---|---|
| DSH 桌面版（Electron） | 默认已授权；若被拒，去系统「设置 → 通知」里允许 DeepSeek Harness |
| 普通浏览器（Chrome/Edge） | 地址栏左侧的站点设置 → 通知 → 允许，然后刷新页面 |
| 仍然不行 | 插件会自动回退应用内弹窗，先把「应用内弹窗」打开当主通道 |

## 5. 排障

| 现象 | 先查什么 |
|---|---|
| 侧边栏没有入口 | DSH 是否重启过；`dsh plugin --profile <profile> list` 里有没有 `dsh-human-alert` |
| 有声音、没系统通知 | 面板「桌面通知」里的权限状态；系统专注助手/勿扰模式；是否把「系统桌面通知」关了 |
| 最小化时收不到 | 同上；另外确认宿主是 v0.3（`/state` 里有 `revision`），旧宿主会退化成每秒轮询、后台被节流 |
| 收到两条（系统通知 + 应用内弹窗） | 「应用内弹窗」被打开了：它默认关闭。想只留一种就关掉其中一个 |
| 面板显示「暂时读不到宿主状态」 | 括号里带具体原因；确认装完插件后重启过 DSH，看 Network 里 `/dsh-human-alert/wait` 的状态码 |
| 面板顶部有红色「… 注册失败」 | 某个 slot 注册被宿主拒绝，消息里有 slot 名与原因 |
| 有弹窗没声音 | 先在页面点一下（解锁自动播放），再看音量是否 0、`声音提醒` 是否开 |
| 任务完成不提醒 | `【任务完成】提醒` 是否开；是不是子 agent（子 agent 不提醒）；这一轮是不是被取消/报错了 |
| 日志是空的 | 日志在**提醒事件到达时**写入；若宿主没在跑（读不到状态），自然没有日志 |

宿主状态接口是只读的，可以直接用命令验证：

```bash
curl -s http://127.0.0.1:19387/dsh-human-alert/health
curl -s http://127.0.0.1:19387/dsh-human-alert/state
# 长轮询：立即返回当前快照（revision 比 since 新时）
curl -s "http://127.0.0.1:19387/dsh-human-alert/wait?since=-1&timeout=100"
```

返回 `{"ok":true,...}` 说明宿主侧已就绪；`/state` 里应有 `revision`、`pending`、`completions`、`completionSeq`。
返回 `403` 说明请求不是从本机回环或带了跨站标记。

## 6. 手工验收清单

自动化能覆盖的部分（124 个用例）已经覆盖了折叠逻辑、两类边沿、设置钳制与迁移、日志环、
宿主集成、长轮询唤醒、客户端产物加载、桌面通知与兜底。下面这些**必须在真实界面里看一眼**：

- [ ] 侧边栏出现铃铛入口，点击能打开面板
- [ ] 面板分区：总开关 / 提醒类型 / 桌面通知 / 应用内弹窗 / 声音 / 文案 / 日志 / 帮助
- [ ] 「桌面通知」里权限显示正确，「申请权限」可用
- [ ] 点「测试审批」→ 右下角出现 `【人工审批】` 系统通知 + 听到声音
- [ ] 点「测试完成」→ 右下角出现 `【任务完成】` 系统通知 + 听到声音
- [ ] 通知**不会**把 DSH 窗口激活（焦点留在正在打字的窗口）
- [ ] 点击系统通知 → 回到 DSH
- [ ] 把 DSH 最小化 → 点一次测试（或触发真实审批）→ 通知仍出现
- [ ] 关掉「系统桌面通知」+ 打开「应用内弹窗」→ 应用内弹窗出现
- [ ] 两个都打开 → 系统通知静音、应用内弹窗响铃（只有一声）
- [ ] 两个都关掉 → 什么都不弹，但日志仍记录
- [ ] 改审批标题为「A」、完成标题为「B」→ 分别测试 → 通知标题分别是 `【人工审批】A` / `【任务完成】B`
- [ ] 关掉「【任务完成】提醒」→ 等一轮跑完 → 无通知，但日志多一条【任务完成】
- [ ] 刷新页面 → 上述设置全部保留
- [ ] 触发一次**真实**审批 → 看到【人工审批】通知 + 日志多一条
- [ ] 等一轮任务正常跑完 → 看到【任务完成】通知 + 日志多一条
- [ ] 日志条目两类标记的文案与颜色不同
- [ ] 点「清空日志」→ 列表清空，刷新后仍为空
- [ ] 页面切到后台再切回：切回后状态仍在同步（不会一直显示"读不到宿主"）
- [ ] 深色主题下面板文字可读（只用了 `--dsw-*` token）

## 7. 卸载

```bash
dsh plugin --profile <profile> remove dsh-human-alert
```

插件注册的所有监听、路由、挂起的长轮询、定时器、音频、系统通知都会随卸载释放
（有单测覆盖：`卸载时路由被解绑`、`卸载后不再继续请求`）。
`localStorage` 里的两条记录会保留，需要彻底清理就在开发者工具里删掉。
