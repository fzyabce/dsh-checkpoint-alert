# dsh-human-alert

当 DSH 走到**需要人**的时刻，用**右下角系统桌面通知**和声音叫你——DSH 最小化、被别的窗口盖住、切到别的页面都能看见。

两类提醒各自独立：

| 类型 | 什么时候响 | 通知标记 |
|---|---|---|
| **【人工审批】** | 工具调用需要你审批（`approval/asked`），或 agent 调用 `ask_user_question` 向你提问 | 警示色 `【人工审批】` |
| **【任务完成】** | 某一轮任务正常跑完（`turn/end` 且 `reason.kind === 'completed'`） | 成功色 `【任务完成】` |

只提醒，不代替你做决定：插件只读监听会话事件，既不批准审批、也不回答提问，更不改任何流程。

## 安装

直接从这个仓库装（把 `<profile>` 换成你的 profile 名，桌面版默认是 `desktop`）：

```bash
dsh plugin --profile <profile> add github:fzyabce/dsh-human-alert
```

仓库里已经带构建好的 `client.js`，源码安装不需要额外跑构建、也不需要 `allowBuilds` 授权。
支持 DSH `0.1.2-rc.1` 起的各版本（含 `0.2.x` 预发布线，peer 范围已写明预发布分支）。

本地开发时直接装目录（同样把 `<profile>` 换成实际名字）：

```bash
dsh plugin --profile <profile> add link:<本目录绝对路径>
```

> `dsh` 不一定在 PATH 上。桌面版通常在
> `D:\DeepSeekHarness\resources\runtime\cli\bin\dsh.cmd`（Windows）
> 或对应安装目录的 `resources/runtime/cli/bin/dsh`。

装完先**重启 DSH**（宿主侧模块在进程内缓存），再**刷新页面**。侧边栏会出现「人工确认提醒」入口。

## 通知长什么样

- 默认是**操作系统通知**（Windows 右下角 toast / macOS 通知中心）：标题形如
  `【人工审批】需要你拍板`、`【任务完成】这一轮任务完成了`，正文是提示文案 + 触发工具/会话/轮次。
- **不抢焦点**：系统通知不会激活 DSH 窗口；点通知才会回到 DSH。
- **置顶**：由系统通知中心叠加在所有窗口之上。
- 同一类只保留最新一条（`tag` 去重），不会堆成一串。

应用内弹窗仍然保留，但默认**关闭**，只在系统通知弹不出来时（没有权限 / 环境不支持 / 系统拒绝）自动兜底；
想同时用两个通道，把「应用内弹窗」打开即可。

## 配置

全部在侧边栏面板里，改动即时生效并写入浏览器 `localStorage`。

| 分组 | 配置项 | 默认值 | 说明 |
|---|---|---|---|
| 总开关 | 启用提醒 | 开 | 关掉后不弹窗不响铃，但日志照常记录 |
| 提醒类型 | 【人工审批】提醒 | 开 | 只关这一类，不影响任务完成提醒 |
| 提醒类型 | 【任务完成】提醒 | 开 | 只关这一类，不影响审批提醒 |
| 桌面通知 | 系统桌面通知 | 开 | 右下角独立系统通知，DSH 最小化也可见 |
| 桌面通知 | 通知权限 | — | 显示已授权 / 未授权 / 被拒 / 不支持，可点「申请权限」 |
| 应用内弹窗 | 应用内弹窗 | 关 | 兜底通道；打开则两个通道都弹 |
| 应用内弹窗 | 始终置顶 / 自动关闭 | 开 / 20 秒 | 只影响应用内弹窗 |
| 声音 | 声音提醒 | 开 | 纯系统通知时交给系统提示音 |
| 声音 | 提示音 / 音量 / 持续响铃 | 内置合成音 / 60 / 开 | 「持续响铃」只在有应用内弹窗时生效 |
| 文案 | 人工审批：标题 / 正文 / 按钮 | 见面板 | 与任务完成文案互不影响 |
| 文案 | 任务完成：标题 / 正文 / 按钮 | 见面板 | 与审批文案互不影响 |

面板右上角有两个测试按钮：**测试审批** / **测试完成**。点击时顺带申请系统通知权限，然后弹对应类型的示例通知，不写日志、不影响真实状态。

## 数据存在哪

只在本机浏览器里：

- `dsh-human-alert:settings:v1` — 设置（值里带 `version: 3`）
- `dsh-human-alert:log:v1` — 提醒日志（最多 200 条）

日志只记**时间、类型、来源（工具审批 / 提问 / 轮次结束）、工具名、会话 id**，不记对话内容。
界面上只渲染最近 50 条（存储上限仍是 200）。

清除：浏览器开发者工具里删掉这两个键，或点面板里的「清空日志」。

## 工作原理

```
宿主：ctx.on('session/event')
        ├─ approval/asked · tool/call(ask_user_question) ──折叠──▶ pending[]（持续状态）
        └─ turn/end(completed)                           ──折叠──▶ completions[] + 单调 seq（一次性边沿）
                  │
                  ├─ GET /dsh-human-alert/state          一次性快照（手工排查用）
                  └─ GET /dsh-human-alert/wait?since=N   长轮询：状态一变立刻回包
                                    │
                        客户端 ──▶ 系统桌面通知 + 声音 + 日志
```

**为什么用长轮询而不是定时轮询**：浏览器会把后台页面的定时器节流（隐藏 5 分钟后可能低到每分钟一次），
纯轮询在 DSH 最小化时提醒会迟到一分钟。长轮询由宿主在状态变化时立刻回包，网络回调不受节流影响，
所以最小化时也能秒级通知；页面隐藏时连接挂着不动，比每秒一次轮询更省。

**「人工审批」是持续状态**：人没处理就一直挂着，`approval/decided` 或 `tool/result` 到达才消失。
**「任务完成」是一次性边沿**：宿主给每条完成记录一个单调递增的 `seq`，客户端只处理比基线大的 `seq`，
推送不会漏，也不会把历史记录当新提醒重复弹。

## v0.3.0 改了什么

1. **桌面系统通知**：新增 `desktopNotifyEnabled`（默认开），右下角 OS 通知代替应用内弹窗成为主通道；
   类型标记、文案、tag 都按【人工审批】/【任务完成】分开。
2. **最小化也能提醒**：客户端从 1 秒定时轮询改成宿主长轮询（`/wait?since=`），不再受浏览器后台节流影响。
3. **兜底不丢提醒**：系统通知弹不出来（无权限/不支持/抛错）时自动回退应用内弹窗；两个通道都关掉才彻底静音。
4. **权限可控**：面板显示通知权限状态并可申请；首次点击页面或点测试按钮时申请（浏览器要求用户手势）。
5. **设置迁移**：v2 设置升级时一次性把「应用内弹窗」关掉，避免老用户同时看到两个弹窗；文案与开关全部保留。
6. **顺手修掉一个真 bug**：`tool/result` 的真实 payload 把 `callId` 放在 `message` 里，v0.2 只读顶层字段，
   导致 `ask_user_question` 结束后提问项永远挂在待确认列表里；现在三种字段名都认。

上一版（v0.2.0）的修复与性能优化见 [`doc/changelog-0.2.0.md`](doc/changelog-0.2.0.md)，
本版细节见 [`doc/changelog-0.3.0.md`](doc/changelog-0.3.0.md)。

## 已知边界

- **DSH 进程完全退出后不会提醒**。通知由页面发起，进程没了就没有东西可弹——这是浏览器内插件的硬边界；
  要"关掉 DSH 也提醒"需要宿主侧常驻服务（不在本插件范围）。
- **系统"专注助手 / 勿扰模式"会压掉 toast**。若最小化时收不到，先看 Windows 通知设置。
- 应用内弹窗打开时，系统通知会静音并由插件自己响铃（避免两声）。
- 子 agent（subagent）的轮次结束**不会**提醒；但子 agent 卡在审批上仍会提醒。
- 取消/报错/被拦截/超长的 turn 不算「任务完成」。
- 浏览器自动播放策略可能让第一次声音静音，页面上任意点击一次即可解锁。
- 某一类提醒被关掉期间到达的项不会在重新打开时补弹（日志里仍有记录）。

## 卸载

```bash
dsh plugin --profile <你的 profile> remove dsh-human-alert
```

卸载后插件注册的监听、路由、长轮询、定时器、音频、通知全部释放。localStorage 里的两条记录会保留，需要的话手动删掉。

## 开发

```bash
npm test              # 124 个用例：折叠 / 设置钳制与迁移 / 日志环 / 宿主集成 / 长轮询 / 客户端产物 / 桌面通知 / 跨两半契约
npm run build         # 由 src/client.template.js + lib/shared/*.mjs 生成 client.js
```

`client.js` 是**构建产物且入库**（宿主要求 `./client` 必须是 lazy-CJS factory 格式）。改客户端请改 `src/client.template.js`，然后重新 `npm run build`。

设计文档、能力规格、任务清单都在 [`doc/`](doc/) 下（OpenSpec 结构）。
